# КОНТЕНТ.ART · Mini App v2

Новая самостоятельная версия, созданная 26.10.2026. Это не восстановленная копия прежнего архива. Визуальная основа — существующий сайт КОНТЕНТ: чёрный фон, лаймовый акцент, «Фабрика миров».

## Что работает

- Адаптивные экраны: главная, направления, заявка, о нас, информация о передаче данных.
- Направления: продакшн, пространство, Контент-школа, мероприятия.
- Форма: имя, контакт, направление, желаемая дата, описание задачи и согласие на передачу данных.
- Авторизация заявки по подписанным Telegram initData; срок действия — 1 час. При истечении нужно открыть приложение заново.
- Доставка заявки администратору через Telegram Bot API. Успех появляется только после подтверждения Telegram.
- Ограничение: 3 новые заявки за 10 минут на Telegram-пользователя. Повтор с тем же номером не отправляет второе сообщение в течение часа, пока процесс работает.
- Просмотр в обычном браузере без токена; отправка доступна только внутри Telegram после настройки сервера.

Нет оплаты, базы клиентов, подтверждённых бронирований, учёта свободных слотов и выдуманных цен. Отправка — запрос команде, а не бронь. Архив не содержит секретов. Каталог редактируется в public/index.html; названия направлений для уведомлений — в server.mjs.

## Проверить на компьютере

Нужен Node.js 22 или новее. В папке проекта:

```text
npm ci
npm test
npm start
```

Открыть http://localhost:3000. Без секретов работает просмотр, отправка отключена. Временный локальный запуск с переменными из собственного .env возможен командой `node --env-file=.env server.mjs`. Обычный `npm start` .env не читает; на Render переменные задаются через Environment.

## Развернуть в Render

Render не принимает этот ZIP как источник. Распакуйте архив и загрузите файлы в Git-репозиторий: package.json и server.mjs должны быть в его корне. Не загружайте сам ZIP вместо файлов.

Если подключение GitHub к Render не открывается, допустим путь Public Git Repository с HTTPS-ссылкой на публичный репозиторий GitHub/GitLab/Bitbucket. Код в таком репозитории общедоступен — сначала убедитесь, что .env и другие секреты отсутствуют. Публикация кода не выполняется этим архивом автоматически. Для закрытого кода нужен подключённый Git-провайдер.

В New → Web Service:

| Поле | Значение |
|---|---|
| Source | Ваш Git-репозиторий |
| Name | kontent-miniapp-v2 или другое свободное имя |
| Language | Node |
| Branch | Ветка с загруженными файлами |
| Root Directory | Пусто, если файлы в корне репозитория |
| Build Command | npm ci --omit=dev |
| Start Command | npm start |
| Health Check Path | /healthz |
| NODE_VERSION | 22 |

Выберите тариф самостоятельно. render.yaml описывает Free; доступность и условия проверяйте в Dashboard. Платный тариф не требуется самим кодом. Бесплатный сервис может засыпать, поэтому первый запуск бывает медленным. Публичный Git URL требует ручного деплоя обновлений.

Можно использовать Blueprint: render.yaml уже включён. Его официальная проверка Render CLI в этой среде не проводилась. Прямое создание Web Service по полям таблицы не требует Blueprint.

## Подключить Telegram безопасно

В Render → сервис → Environment добавьте:

- TELEGRAM_BOT_TOKEN — токен существующего бота из @BotFather. Вводите только в Render. Не отправляйте его в чат, не добавляйте в HTML, JavaScript, Git, render.yaml, скриншоты или переменные VITE_/NEXT_PUBLIC_.
- TELEGRAM_ADMIN_CHAT_ID — числовой ID вашего личного чата с ботом или закрытой группы команды (у группы обычно отрицательный). Не используйте случайные сторонние боты для поиска ID. Сначала администратор должен открыть вашего бота и нажать Start; для группы добавьте бота с правом отправки сообщений.
- BOT_USERNAME — необязательно: имя бота без @. Нужен для ссылки «Открыть бота в Telegram» при просмотре в браузере.

Нажмите Save and deploy / Save, rebuild, and deploy. Никогда не вставляйте токен в адресную строку браузера для вызова Bot API. Если токен уже был опубликован, отзовите его у BotFather и замените в Render.

После Live:

1. Откройте HTTPS-адрес сервиса *.onrender.com, проверьте все экраны; /healthz должен вернуть status=ok.
2. В @BotFather выберите своего бота, настройте кнопку меню Mini App через /setmenubutton и задайте HTTPS-адрес сервиса. При необходимости настройте Main Mini App в разделе Bot Settings → Configure Mini App. Обычный запуск этого сервера не меняет настройки бота, не создаёт polling и не трогает существующий webhook.
3. Откройте кнопку меню бота, отправьте тестовую заявку и проверьте реальное сообщение в чате администратора. Контакт, направление и дата должны совпасть.
4. Если доставка не подтверждена, проверьте токен, ID чата, Start у бота и права бота в группе. Приложение намеренно не выводит подробности ошибок Telegram с потенциальными секретами.

## Домен app.контент.art и HTTPS

Сначала добейтесь работающего сервиса *.onrender.com и реальной доставки тестовой заявки. До этого DNS REG.RU не менять.

Затем добавьте поддомен в Settings → Custom Domains, используя Punycode для кириллической части (Render требует ASCII-имя). Только после этого у DNS-провайдера измените запись именно для app на значение CNAME, указанное Render. Не трогайте основной домен, почтовые записи и другие поддомены. Конфликтующие A/AAAA для app проверьте по актуальной инструкции Render. Дождитесь Verified и действующего TLS-сертификата, проверьте https://app.контент.art и только затем замените URL Mini App у BotFather. Render выпускает и продлевает сертификат автоматически; существующий приватный ключ REG.RU здесь не нужен.

## Данные и границы проверки

Сервер не сохраняет заявки на диск. Telegram хранит сообщения по своим правилам. В памяти процесса на час хранится номер и содержимое заявки для защиты от повторов; перезапуск сбрасывает эту защиту и лимиты. При сетевой неопределённости Telegram мог получить сообщение даже без полученного ответа: повтор может доставить дубль с тем же номером, который виден администратору. Для масштабирования и строгой дедупликации нужна внешняя БД.

Оператору следует дополнить публичные сведения об обработке данных своими реквизитами, контактами и фактическим порядком хранения перед широким запуском. Имена, адреса и юридические реквизиты владельца не выдуманы.

Локальные тесты проверяют подпись Telegram, просроченные и подменённые данные, отсутствие согласия, доставку через подставной транспорт, повторы, лимиты и скрытие токена. Они не доказывают доставку в ваш реальный чат: это проверяется только после ввода секретов и запуска в Telegram.
